# 关卡覆盖与 FFI 门禁

判定只有两项（`tools/gate.py`）：

- **no_crash**：抓到的调用全部在我们的 DLL 上执行完，不崩；
- **bounded**：每步超差 body 数**不再增长**——跳过前 10% 加载期，比较最后两个十分位的中位数（近端斜率 ≤ ×1.25+2），并额外报出峰值水位。

抓包方式：面板用**原版 DLL**（代理占位）跑游戏，人在游戏里正常玩，FFI 写入 `work/rec_*/ffi.bin`。
游戏内行为由人工验证（面板「试玩替换 DLL」按钮）。

> 判据：`no_crash` + `bounded`（末两个十分位中位数 ≤ 前段×1.25+2，跳过前 10% 加载期；F56/F65）。`逐位首发` 是不受容差影响的严格口径。
>
> **这条结论能撑多重**：判据是个数（每步超差 body 数是否还在涨），不是幅度——`末段幅度` 是末个十分位里最坏一具 body 的 |Δ|/容差，被磁力/马达驱动的自由飞行体会把它放大到 1e5 倍，但个数饱和就仍是 PASS（F73）。
>
> **噪声地板**：A/A 地板按录制分别量（F125）——把同一份日志重放到原版 DLL（`python tools/sweep.py --floors`，缓存 `work/floors.json`）得到的 `bodies_bad` 就是该录制的 `地板` 列（`—` = 未算）。「bad 非零」只在**高于地板**时才是差异；地板为 0 时剩下的 denormal 级差（1e-23 量级，重放进程 FPU/MXCSR 与原版游戏内状态不完全一致，F91⑤）仍属噪声。
>
> **高于自身地板**（需要看的第一批）：`rec_20261029_134716`（4825 > 0）。
>
> **仪器覆盖不到**：摘要只含 body 的 flags/sleepTime/位置/角度/速度/质量/惯量；关节冲量、`sweep.c0/a0`、接触热启动冲量、broadphase fat AABB 都不在其中——差异出现在「已覆盖部分逐位相同之后」时，正确结论是「在这里看不见」（F88/F91/F92）。
<!-- sweep:end -->

> **保真度基线（F72/F73）**：原版 DLL 自放同一份日志 = **0 差异**（302,032 次 body 比对），所以我们的差异都是实现本身的浮点级偏差，不是录制噪声；首分叉恒为 1e-4 量级，在自由飞行/马达驱动的 body 上会放大但传送后合拢。

> **每关的验证顺序（自 hammer 起）**：自造 DLL 试玩（人工确认可解、不崩）→ 代理 DLL 录制 `ffi.bin` → 离线门禁。所以 `no_crash` 的证据来自人工试玩，门禁的独立价值在 `bounded`。

> **随机初始化关卡**：`looking for keys`（`lvl_o8`）等 8 个脚本用 `math.random()` 布景，每次进关场景不同 → **鼠标宏无法复现**，这类关卡只能靠 FFI 重放做门禁，人工验证退化为「进关看不崩」。

> **注意**：`looking for keys` 是保真度波动最灵敏的一关（随机关 + 体数最多），做回归时优先看它；`the stones` 与 `the electric circuit` 相反，是稳态最干净的两关（3 万步只有千级超差）。

> **日志格式**：全套录制在 `replay_ffi` 改成 **LIFO 栈配对**（修复嵌套 pre/post，F63）之后重跑过。三份 v01 日志（`B2FFI01`，64B dump：邮件关旧录、地图关、first totem）按 F87 判定不可作保真度判据，表里记 `UNUSABLE`；这三关都已用 v02 重录补上（邮件关 `rec_ct`、Get the Map `rec_20261029_183833`、The First Totem `rec_20261029_183942`，F101），因此 **52 关全部有可判定语料**。

## 共同特征

首个分歧几乎总是 `sleepTime`（我们 0、原版 0.1~0.2）——休眠计时在阈值附近的抖动，属已接受的噪声；
`mass / flags / 位置 / 速度` 在前 ~150 步逐字段一致。
